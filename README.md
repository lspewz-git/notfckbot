# NotFckBot — Телеграм-бот для отслеживания сериалов и фильмов

Бот позволяет подписываться на сериалы и получать уведомления о выходе новых серий, а также вести список ожидания фильмов и узнавать об их выходе. Данные берутся через [TMDB API](https://www.themoviedb.org/).

## Возможности

**Бот**

- 🔍 **Поиск** сериалов и фильмов по названию.
- 📺 **Подписки на сериалы**: три режима уведомлений — каждая серия, весь сезон, первая серия сезона + сезон целиком. «Весь сезон вышел» приходит, только когда TMDB не анонсирует больше серий этого сезона.
- 🗂 **Мои подписки** — одно сообщение, которое меняется на месте: обзор текстом, «⚙️ Настроить подписки» (режим, отписка с подтверждением) и «🗄 Завершённые».
- 🏁 **Архив завершённых сериалов**: когда TMDB помечает сериал как Ended или Canceled, бот сообщает об этом и переносит подписку в «Завершённые»; если сериал продлят — сообщит и вернёт в активные. При подписке на уже завершённый сериал бот предупреждает.
- 🎞 **Список ожидания фильмов**: бот следит за датой выхода (дата и название обновляются при каждой проверке) и пишет, когда фильм вышел; если TMDB знает дату цифрового релиза, она указана в уведомлении.
- 🔗 **Ссылки на просмотр** в уведомлениях: HDRezka, SSPoisk и страница на Кинопоиске (см. «Ссылки на просмотр»).
- 🎲 **Случайный фильм**: подбор наугад.
- ⚡️ **Проверка обновлений** каждые 3 часа (cron).
- 👥 **Группы**: работает и в личных чатах, и в групповых.
- 🛡 **Антиспам**: повтор одного и того же сообщения подряд блокирует на 5 минут с объяснением; нажатия кнопок лишь ограничены по частоте.

**Админ-панель**

- Дашборд: чаты, активные подписки (+ архив), фильмы в ожидании (+ вышедшие), число отслеживаемых сериалов и три карточки одного размера:
  - **Coming up** — пять ближайших выходов: следующие серии подписанных сериалов и даты релиза ожидаемых фильмов;
  - **Update check** — как прошла последняя проверка обновлений (когда, сколько длилась, сколько сериалов и фильмов проверено, ошибки, отправленные и недоставленные уведомления) и когда будет следующая. Итог проверки бот сохраняет в `.cron-status.json` в папке проекта, чтобы он пережил перезапуск;
  - **Popular now** — самые популярные сериалы.
- Индикаторы **TG**, **TMDB**, **KP** и **Proxy**. Клик по TG/TMDB/KP открывает окно сервиса: статус, квота (у Кинопоиска), токен в маске (`ad5d*****659d`), замена токена с проверкой у самого сервиса и ссылка на страницу статуса.
- Автообновление данных (по умолчанию **на паузе**) и обновление по кнопке.
- Пользователи и чаты: одно меню действий на строку — сообщение, блокировка, добавление сериала или фильма общим поиском.
- **Serials** (подписки на сериалы): вкладки **Active / Archive** (завершённые и отменённые сериалы), статус из TMDB, следующая серия с датой (**Next Episode**, `TBA`, если не анонсирована; обновляется при каждой проверке) и смена режима уведомлений.
- **Movies** (список ожидания фильмов): вкладки **Waiting / Released**, дата выхода, сортировка по году и дате релиза по клику на заголовок колонки (на телефоне — строка **Sort** над карточками).
- Карточка сериала или фильма по клику на название: постер, рейтинг, дата, описание и число подписчиков. Постеры отдаёт сервер (`/api/poster/…`), потому что `image.tmdb.org` доступен не из всех сетей. Данные карточки сервер держит в кэше до 6 часов; проверка обновлений раз в 3 часа освежает его для всех отслеживаемых тайтлов, так что повторное открытие не обращается к TMDB.
- Поиск по таблицам, скелетоны на время загрузки.
- Настройка прокси прямо из панели — по клику на индикатор Proxy.
- Рассылка с выбором аудитории и просмотр логов приложения.
- **Danger Zone** — полная очистка базы с подтверждением.
- Тёмная плотная тема (токены и правила — в [`admin/DESIGN.md`](admin/DESIGN.md)), доступность: контраст AA, видимый фокус, `prefers-reduced-motion`.
- Адаптивная вёрстка: на телефонах и планшетах вместо бокового меню — нижняя панель вкладок (Dashboard · Chats · Serials · Movies · More), таблицы становятся карточками.

> ⚠️ У панели **нет аутентификации**: кто дотянулся до адреса, тот и администратор — может делать рассылки, удалять данные и менять токены. В `docker-compose.yml` порт проброшен на все интерфейсы, то есть панель видна всей локальной сети. Не выставляйте её в интернет без внешней защиты (VPN, реверс-прокси с авторизацией). Секреты панель наружу не отдаёт: токены и пароль прокси показываются только в маске.

## Технологии

- Node.js + Telegraf (Telegram Bot API)
- Sequelize ORM + MariaDB
- Express — API и раздача панели
- Docker + Docker Compose
- Axios + socks-proxy-agent / https-proxy-agent — исходящий трафик через прокси
- node-cron — планировщик
- Фронтенд панели — нативные ES-модули без сборки: браузер получает ровно те файлы, что лежат в репозитории

## Как запустить

### 1. Подготовка

Создайте файл `.env` на основе `.env.example`:

```env
BOT_TOKEN=ваш_токен_от_BotFather
TMDB_API_KEY=ваш_ключ_от_themoviedb.org

DB_HOST=db
DB_NAME=series_bot
DB_USER=bot_user
DB_PASSWORD=bot_password
MARIADB_ROOT_PASSWORD=root_password

# Необязательно: прокси (см. раздел «Прокси»)
TMDB_PROXY_URL=

# Необязательно: ключ kinopoiskapiunofficial.tech (см. раздел «Ссылки на просмотр»)
KINOPOISK_API_KEY=
```

`.env` — главный источник настроек: при старте он перекрывает переменные, которые docker-compose передал контейнеру. Поэтому токены и прокси, изменённые в панели (она пишет их в `.env`), переживают перезапуск.

### 2. Запуск через Docker (рекомендуется)

```bash
docker compose up -d --build -V
```

Поднимутся MariaDB и приложение. База сохраняется в volume `mariadb_data`.

`-V` пересоздаёт папку `node_modules` контейнера из нового образа. Без него после изменения зависимостей бот продолжит работать со старыми пакетами: код подключается с диска (`.:/app`), а `node_modules` живёт в отдельном томе.

Готовые скрипты — то же самое одной командой: `start.sh` / `start.bat` (сборка и запуск), `stop.sh` / `stop.bat` (остановка), `logs.bat` (логи).

Если менялся только код (`src/`, `admin/`), пересборка не нужна: файлы подключены с диска, достаточно `docker compose restart app` (для `admin/` — просто обновить страницу).

Логи:

```bash
docker compose logs -f app
```

### 3. Запуск локально (для разработки)

1. Установите зависимости:
    ```bash
    npm install
    ```
2. Запустите MariaDB и проверьте настройки в `.env` (для локального запуска `DB_HOST=db` автоматически подменяется на `localhost`, если не выставлен `IS_DOCKER`).
3. Запустите приложение:
    ```bash
    npm start
    ```

## Команды бота

- `/start` — главное меню и инициализация чата.
- `/search` — поиск сериала или фильма.
- `/subs` — список подписок.
- `/random` — случайный фильм.
- `/help` — справка.
- `/cancel` — отменить текущее действие.
- `/menu_off`, `/menu_on` — скрыть или показать кнопки клавиатуры.
- `/reset` — сбросить состояние чата.

Также доступны Reply-кнопки: 🔍 Поиск, 📺 Мои подписки, 🎲 Случайный фильм, ℹ️ Помощь.

## Прокси

Один адрес в `TMDB_PROXY_URL` управляет **всем исходящим трафиком приложения** — и запросами к TMDB, и Telegram Bot API. Подключение к MariaDB идёт напрямую внутри docker-сети и прокси не касается.

Поддерживаются схемы `http://`, `https://`, `socks5://` и `socks5h://`, с логином и паролем или без:

```
socks5h://user:pass@10.0.0.5:1080
```

Настраивается двумя способами: переменной в `.env` или прямо в панели — клик по индикатору **Proxy** в шапке. Второй способ применяется сразу, без перезапуска, и там же есть кнопка **Test**, которая проверяет кандидата на реальном запросе к TMDB **до** сохранения. Пароль прокси в панель не передаётся: поле пароля пустое, и если оставить его пустым, сохранится прежний пароль (для того же пользователя и хоста).

О DNS: `http(s)` и `socks5h` разрешают имя на стороне прокси, а обычный `socks5` — локально. Если проблема именно в подменённом DNS (симптом — `ECONNREFUSED 127.0.0.1:443`), выбирайте `socks5h`.

## Ссылки на просмотр

В уведомлениях о новых сериях, сезонах и вышедших фильмах бот даёт три ссылки:

- **Смотреть на HDRezka** — поиск по названию;
- **Смотреть на SSPoisk** и **Страница на Кинопоиске** — прямо на страницу тайтла (`sspoisk.ru/film/ID` повторяет адреса Кинопоиска).

Для двух последних нужен ID Кинопоиска. Бот берёт его из Wikidata по TMDB ID (без ключа и лимитов), а если там тайтла ещё нет — из [kinopoiskapiunofficial.tech](https://kinopoiskapiunofficial.tech) по IMDb ID, если задан `KINOPOISK_API_KEY` (бесплатный ключ — 500 запросов в день). Найденный ID сохраняется у сериала; не найденный ищется снова раз в сутки. Без ID ссылка на Кинопоиск ведёт на поиск, а SSPoisk не показывается.

Состояние API и расход квоты видны в панели — индикатор **KP** в шапке дашборда; по клику открывается окно с квотой, ключом в маске и ссылкой на [страницу статуса](https://kinopoiskapiunofficial.tech/status).

## Разработка

### Проверка кода

Линтер, форматтер и проверка типов запускаются одной командой — локально, в папке проекта (в образ бота инструменты разработки не попадают):

```bash
npm install
npm run check
```

По отдельности: `npm run lint`, `npm run format:check`, `npm run typecheck`.
Исправить автоматически — `npm run lint:fix` и `npm run format`.

Типы проверяются через JSDoc и `checkJs` (`admin/jsconfig.json`) — сборки нет, в браузер уходят те же файлы. Охват — `admin/js/`; бэкенд не включён, для него нужны типы установленных пакетов.

### Браузерные тесты

Playwright прогоняет основные сценарии панели в Chromium и в WebKit с профилем iPhone 12 mini:

```bash
npx playwright install chromium webkit
```

```bash
ADMIN_URL=http://<host>/ npm test
```

Тесты только читают: диалоги открываются и закрываются, ничего не создаётся, не изменяется и не удаляется, поэтому их безопасно направлять на рабочий экземпляр. Панель они не поднимают — она должна быть уже запущена. Разрушающие сценарии (рассылка, очистка базы, удаления) не покрыты именно поэтому.

## Тестирование уведомлений

В панели: **Actions → Send test notification** или меню чата **⋯ → Send test notification**. Выбираете чат, сериал (из отслеживаемых или поиском в TMDB) и режим — в чат уходит ровно то сообщение, которое бот отправил бы подписчику, с пометкой «Тестовое уведомление». Ничего в базе не меняется и другим подписчикам ничего не приходит.

## Служебные скрипты

- `reset-db.js` — полный сброс базы: удаляет все таблицы и создаёт их заново. Необратимо.

## Структура проекта

**Бэкенд**

- `src/index.js` — точка входа: инициализация БД, бота, cron и панели.
- `src/bot.js` — логика бота и обработка команд.
- `src/admin.js` — HTTP API и раздача панели.
- `src/cron.js` — фоновая проверка обновлений.
- `src/proxy.js` — единая точка сборки прокси-агента для TMDB и Telegram.
- `src/api/tmdb.js` — клиент TMDB.
- `src/api/kinopoisk.js` — поиск ID Кинопоиска (Wikidata, kinopoiskapiunofficial.tech, с кешем) и статус API.
- `src/constants.js` — общие подписи, статусы завершённых сериалов, форматирование дат и ссылки на просмотр.
- `src/models/` — модели БД: `Chat`, `Series`, `Subscription`, `Watchlist`.
- `src/db.js`, `src/database.js` — Sequelize и подключение к MariaDB.

**Фронтенд панели** (`admin/`)

- `index.html` — разметка; обработчики навешиваются делегированием, инлайновых `onclick` нет.
- `js/` — 17 ES-модулей с однонаправленными зависимостями:
  `dom` · `api` · `store` · `render` · `format` → `ui` · `select` → `tables` · `dashboard` · `logs` → `data` → `chats` · `records` · `maintenance` · `proxy` · `services` → `app`.
- `css/` — 10 файлов, подключаются в порядке каскада: `base` (токены дизайна), `layout`, `cards`, `logs`, `tables`, `buttons`, `forms`, `overlays`, `utilities`, `responsive`.
- `DESIGN.md` — дизайн-система: палитра, типографика, отступы, компоненты.
- `jsconfig.json` — настройки проверки типов.

**Прочее**

- `tests/` — сценарии Playwright.
- `eslint.config.mjs`, `.prettierrc.json`, `playwright.config.js` — конфигурация инструментов.
